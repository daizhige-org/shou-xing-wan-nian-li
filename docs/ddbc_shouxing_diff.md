# DDBC 與壽星萬年曆歷史月表差異報告

生成來源：
- DDBC：`authority_time/authority_time.sqlite` 的 `v_month_context`，只比較 `status = S`。
- 壽星：直接載入 `v5.09.04/calendar-core.js`，用 `SSQ.calcY()` 生成同時段朔望月。

## 範圍

- DDBC 正式月記錄：17,227 條。
- DDBC 唯一朔日：10,025 個，JD 1641025 到 1925020。
- 壽星生成月記錄：9,685 條，覆蓋 JD 1640020 到 1925995。
- DDBC 月表實際覆蓋秦至公元 558 年左右；唐以後年號存在於名稱表，但沒有對應月表。

## 規範化規則

- `冬` 視為 `十一`，`腊/臘` 視為 `十二`。
- `后九` 視為 `後九`。
- `閏六` 這類 DDBC 月名會拆成「月名=六、閏月=1」比較。
- DDBC `leap_month=2` 多見於 `後九`，不按普通閏月處理：比較時規範化為 leap=0，另列觀察。

## 總覽

- 朔日完全命中：9,490 / 10,025。
- DDBC 朔日未在壽星月表找到完全相同 JD：535。
- 其中可用 ±1 日解釋：428，分布：{-1: 299, 1: 129}。
- ±1 日內仍找不到對應壽星朔日：107。
- 壽星在 DDBC 範圍內額外朔日：128。
- 完全同朔日但月長不同：398 條 DDBC 記錄。
- 完全同朔日且規範化後月名/閏月不同：133 條 DDBC 記錄。
- DDBC 改元/狀態切分月 `start_from > 1`：117 條。
- DDBC `leap_month=2` 記錄：44 條。

## 主要判讀

1. 朔日差異大多是 ±1 日，集中在早期歷法與 DDBC 特定校訂點，適合人工抽查。
2. `start_from > 1` 的記錄通常不是整月差異，而是改元或正統/推衍狀態在月內切分；接入時不能當普通朔望月直接覆蓋。
3. 月名差異有兩類：一類是顯示寫法，已被規範化；另一類是真正月序不同，例如 DDBC 和壽星對某年歲首或後九月處理不同。
4. DDBC 記錄常常同一朔日對應多個並行政權，做 UI 接入時需要選擇展示政權或提供多候選。
